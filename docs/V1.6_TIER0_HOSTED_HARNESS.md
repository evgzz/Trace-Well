# V1.6 Tier-0 hosted harness

Experimental scripts for the hosted Path A of the [real-model runbook](V1.6_REAL_MODEL_RUNBOOK.md). They automate Tier-0 transport checks against one dedicated Hugging Face Inference Endpoint. Output is `transport_only` evidence; nothing here establishes judge validity, calibration, or semantic-only FAIL authority.

This harness is a draft experiment surface. It is not part of the V1.5 or V1.6 acceptance record.

## Files

| File | Role |
|---|---|
| `scripts/tier0_admission.py` | Control-plane admission and pause; the only code that imports `huggingface_hub` |
| `scripts/tier0_codespace.sh` | Orchestrates G0–G4 in one Bash scope |
| `scripts/tier0_hf_run.py` | Builds the fixture request and runs the semantic pipeline through the adapter |
| `scripts/tier0_capture_judge.py` | Runs `hf_endpoint_judge.py` unchanged and saves wire bytes per call |
| `cases/semantic/sem-004-real-violation.yaml` | Fixture with a deterministic FAIL pair for the real judge |
| `tests/test_tier0_harness.py` | Offline tests: admission, protected paths, cleanup, payload contract |

## Environment

| Variable | Required | Notes |
|---|---|---|
| `HF_TOKEN` | yes | Codespaces secret; revoke after the run |
| `HF_ENDPOINT_NAME` | yes | Approved endpoint name for the control-plane lookup |
| `HF_ENDPOINT_NAMESPACE` | no | Owner namespace, when not the token's own |
| `HF_ENDPOINT_URL` | yes | Configured inference URL; must pass the adapter's exact-host rules against the control-plane host |
| `HF_REVISION` | yes, no default | Approved 40-character commit SHA, chosen before the run |
| `HF_API_MODEL`, `HF_ENGINE`, `RUN_ID` | no | Defaults: the Tier-0 model id, `vllm`, `tier0-qwen-hf-001` |
| `TIER0_REPEATS` | no | Adapter repetitions, an integer from 1 to 10 (default 3; keep 3 for the initial experiment unless separately approved) |
| `TIER0_BUDGET_ACK` | yes | The budget id from the run-budget report; the script stops before G0 without a matching value |
| `TIER0_PAUSE_ON_EXIT` | no | `1` (default) pauses an admitted endpoint on exit |
| `TIER0_PAUSE_CONFIRM_SECONDS`, `TIER0_PAUSE_POLL_SECONDS` | no | Polling deadline for `paused` after the pause request (default 300) and how often to re-read state (default 5) |
| `TIER0_PAUSE_COMMAND_SECONDS` | no | End-to-end limit on the whole pause command, including a blocked control-plane call (default 420); must exceed the polling deadline |
| `TIER0_CURL_CONNECT_SECONDS`, `TIER0_CURL_MAX_SECONDS` | no | Connect limit (default 30) and total-time limit (default 660) for each G1/G2 `curl` call; the total limit must exceed the 600 s scale-up timeout the wake-up requests |
| `TIER0_OUT_DIR` | no | Defaults to the ignored `results/real-model/$RUN_ID` |

`HF_EXPECTED_HOST` is never supplied by the operator. The script derives it from admission.

## Run budget

Before G0 and before admission, the script validates `TIER0_REPEATS`, then prints a run-budget report and saves it as `budget_report.json`. The report records:

- the exact commit, and whether the worktree has uncommitted changes;
- the repeat count and every timing limit;
- an allowance for each bounded stage:

  | Stage | Allowance |
  |---|---|
  | G1/G2 `curl` | 3 requests × `TIER0_CURL_MAX_SECONDS` |
  | G3/G4 judge | `TIER0_REPEATS` × the pipeline's judge subprocess timeout (150 s) |
  | Cleanup | `TIER0_PAUSE_COMMAND_SECONDS` + 10 s termination grace |

- what the total does **not** cover: G0 setup, the authenticated admission lookup (which has no per-call SDK limit), local orchestration and file operations, and endpoint billing after the process exits, including when cleanup fails.

The total is an **estimate over the bounded stages only**. It is not a guaranteed maximum run time and not a cost cap. Spending limits, supervision and a manual stop procedure belong to the separate authorization of a paid run.

The report ends with a 12-character budget id, a digest of the whole report. The run continues only when `TIER0_BUDGET_ACK` equals that id. Because the id changes with the commit, the worktree state, the repeat count or any limit, an acknowledgment covers exactly the configuration that was reviewed. To get the id, run once without `TIER0_BUDGET_ACK`. The script prints the report and stops before G0, and nothing reaches the control plane or the endpoint.

## Admission policy

Before any bearer token reaches the inference host, `tier0_admission.py admit` reads the endpoint from the authenticated control plane and requires:

- state exactly `running` or `scaledToZero`. `paused`, missing, unknown and all other states stop the run. The script never resumes an endpoint;
- repository equal to the runner's `MODEL_ID`, which admission reads from `scripts/tier0_hf_run.py`; the shell keeps no copy;
- revision equal to the operator's `HF_REVISION`, which must be an immutable 40-character SHA;
- an HTTPS control-plane URL, from which `HF_EXPECTED_HOST` is taken;
- the control-plane URL and `HF_ENDPOINT_URL` both passing the adapter's exact-host and origin-path rules against that host. Both normalize to the same origin, so `https://host` and `https://host/v1/` are treated as equal. `HF_ENDPOINT_URL` is checked first and only then replaced by the admitted origin.

Admission writes one JSON object to stdout. The script reads its fields with a JSON parser and never `eval`s it.

## Stages and protected paths

| Stage | Request | Token |
|---|---|---|
| G0 | branch, ignore rule, `pytest`, public-text scan | — |
| G1 admission | control-plane lookup | control plane only |
| G1 probe | `GET /v1/models` on the admitted origin, expects 401/403 | no |
| G1 wake-up | `GET /v1/models` on the admitted origin, expects 200 | yes |
| G2 | direct `POST /v1/chat/completions` on the admitted origin | yes |
| G3/G4 | runner → capture wrapper → adapter, with `--base-url` set to the admitted origin and `--expected-host` | yes |

Every `curl` uses `-q` first, `--proto '=https'`, `--max-redirs 0`, and `--connect-timeout` and `--max-time` limits, so a stalled G1/G2 request cannot keep the run from reaching cleanup. Token-bearing calls add `--fail-with-body`, and each call requires an explicit status. The adapter re-checks the host and refuses redirects independently.

Cleanup pauses only the endpoint identity returned by admission. If admission fails, the endpoint state is left unchanged. A pause counts as done only when the endpoint's state reads exactly `paused`: the pause request is sent once, then the state is re-read until it is `paused` or the confirmation time runs out. All timing settings must be short positive decimals (at most 5 integer and 3 fractional digits, so under 100000 s) and are checked at startup, before admission, so a bad value cannot surface only at cleanup. GNU `timeout` treats `inf` and `0` as no limit, and an overlong decimal becomes `inf` in Python and `awk`, which is why these are rejected. The polling deadline bounds the re-read loop, and a sleep never runs past it. It does not bound a single control-plane call that blocks; the script runs the pause command under `timeout` with the end-to-end limit for that. If the pause request fails, hangs past that limit, or `paused` is not confirmed in time, the script writes `cleanup_failed.txt`, separate from the inference results. It then exits 3, or keeps the run's own non-zero status if the run had already failed, so automation cannot read an unpaused endpoint as a clean run.

## Offline checks

Run all four with inference credentials cleared:

```bash
(
  set -e
  unset HF_TOKEN HF_ENDPOINT_NAME HF_ENDPOINT_URL HF_EXPECTED_HOST
  python -m pytest
  python scripts/check_public_text.py
  python scripts/demo.py
  python scripts/reproduce_po9.py
)
```

The harness tests use a fake `huggingface_hub` package, a recording fake `curl`, and a `sitecustomize` loaded by every Python process the script starts. The `sitecustomize` records and stops any judge process (G3/G4) before its script runs, wherever in the script that process starts. It also blocks and records Python `socket.connect`/`connect_ex` attempts. That is a guard on Python's connection paths, not a complete network sandbox: native executables other than the faked `curl` are not covered. The tests prove a protected path was not invoked from these invocation logs; missing output files are secondary evidence.

The admitted-path tests stop the judge on purpose. A zero exit there shows the script reaches every protected call with the admitted origin and host. It does not show that inference or adapter transport succeeds; that needs a separately authorized live run.

`TIER0_SKIP_SETUP=1` skips the G0 setup gates: the main-branch guard, the dependency install, `pytest` and the public-text scan. It exists so the offline tests can run the script. It is a convenience switch, not a security boundary: anyone can set it, and it does not affect admission, host binding or the request paths.

`tests/fixtures/hf_endpoint_default_payload.json` pins the adapter's default request bytes. Tests never regenerate it. A PR that changes it must explain the prompt, parameter or serialization change.

## Decision record

No new ADR. The harness applies existing decisions: credential host binding from the runbook and PR #20, judge provenance binding (ADR-0021) and semantic-judge isolation (ADR-0017). It adds no verdict semantics and changes no V1.5 behavior. If the harness is ever proposed for merge to `main`, its admission policy should be recorded as a Proposed ADR first.

## Evidence status

Any hosted runs made with earlier revisions of these scripts predate admission and host binding. They are not evidence under this procedure. No run has been performed with this version. A live run needs separate explicit authorization.
