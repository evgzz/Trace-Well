# TRACE-Well V1.6 — Semantic-Judge Scope

## Branch and freeze boundary

V1.6 semantic-judge work is developed on `semantic-judge-v1.6`.

The V1.5 freeze point is commit:

```text
791c92c3da43e33a2e986e63f2f7ef9f845ac70b
```

A convenience branch, `freeze/v1.5.0-pending-po9`, points to that commit. The commit SHA is the immutable evidence anchor; the branch name is only a human-readable reference.

V1.5 remains **Done** with blind independent-human PO-9 signoff pending. V1.6 work must not be used to retroactively expand V1.5 claims.

## Objective

V1.6 extends the deterministic evaluation kernel with an **isolated semantic-judge capability** for constructs that cannot be resolved mechanically from observable trace evidence alone.

The semantic judge is an evaluation component, not ground truth.

## Implemented V1.6 milestones

The current branch implements:

1. strict `JudgeRequest` / `JudgeResponse` JSON protocol;
2. out-of-process semantic-judge execution;
3. deterministic mock judge and protocol failure tests;
4. timeout, non-zero-exit, malformed-output, schema-validation, and request-ID mismatch handling;
5. explicit judge provenance and first-class decoding determinism class;
6. conservative verdict integration preserving V1.5 precedence;
7. end-to-end semantic fixtures with separately persisted `semantic_result.json`;
8. deterministic-only `SafetyFinding` authority;
9. a localhost-only OpenAI-compatible adapter for a real local/open model server, implemented with Python standard-library HTTP only;
10. a blinded calibration harness that joins opaque item IDs to independent human labels and records agreement/disagreement evidence without changing runtime authority.

## Current evidence status

The adapter contract can be tested in CI against a fake loopback OpenAI-compatible server. This demonstrates protocol compatibility and provenance capture; it is **not** real-model validation.

A real local/open model may be connected behind the same subprocess JSON contract, but no real-model calibration claim exists until actual judge outputs are compared against blinded human/domain-expert labels.

The calibration harness explicitly records:

```text
semantic_fail_authority_granted: false
statistical_validity_claimed: false
```

A calibration report therefore remains evidence for evaluation engineering, not a source of runtime verdict authority.

## Explicit non-goals for the current milestone

The current milestone does **not** include:

- hosted-provider integration;
- model SDK or inference dependencies in the base runtime;
- semantic-only FAIL authority;
- semantic-only `SafetyFinding` creation or closure;
- confidence-score thresholds;
- multi-judge voting;
- statistical reliability claims;
- claims of calibration until actual blinded human labels have been collected and compared;
- clinical validity, efficacy, or safety claims;
- production release-governance use.

## Observable-evidence boundary

Semantic judge requests are constructed only from an explicit allowlist of observable trace fields:

```text
event_id
event_type
actor
input
output
tool
tool_arguments
tool_result
authorization_state
evidence_refs
```

`TraceEvent.metadata` is intentionally excluded. Fixture markers, hidden controls, internal annotations, and future non-observable scaffolding must not leak into semantic-judge input.

## Verdict precedence

V1.6 preserves the existing deterministic precedence before considering semantic judgment:

```text
1. global specification inconsistency -> REVIEW
2. established deterministic obligation failure -> FAIL
3. unresolved required deterministic construct -> REVIEW
4. semantic-judge result may be considered only if 1-3 do not already determine the outcome
```

Therefore:

- a semantic judge cannot erase a deterministic `FAIL`;
- **global specification inconsistency still outranks deterministic `FAIL`** because the specification is not reliable enough to support behavioral adjudication;
- semantic uncertainty remains `REVIEW`;
- whether a semantic-only violation may become final `FAIL` remains unresolved under ADR-0015.

## Semantic-only FAIL authority

ADR-0015 remains **Proposed**.

For the current milestone, a semantic judge may produce a structured candidate judgment, but the project does not grant semantic-only judgment final FAIL authority. That decision requires actual calibration evidence and an explicit ADR-0015 resolution.

## Finding authority

`SafetyFinding` authority remains **deterministic-only**.

A `SafetyFinding` may be created only from the frozen V1.5 deterministic pair result. Semantic output is persisted separately as `semantic_result.json` and cannot create, close, or mutate a `SafetyFinding`.

Required examples:

```text
deterministic PASS + semantic candidate PASS   -> integrated PASS   -> no finding
deterministic PASS + semantic candidate FAIL   -> integrated REVIEW -> no finding
deterministic PASS + semantic candidate REVIEW -> integrated REVIEW -> no finding
deterministic FAIL + semantic candidate PASS   -> integrated FAIL   -> deterministic finding remains
```

If a future implementation grants semantic-only FAIL or finding authority, ADR-0015 must first be resolved and the finding lifecycle must be updated explicitly. It must not emerge accidentally from integration code.

## Judge provenance

Every semantic-judge execution must persist enough information to answer both:

1. **what judge ran?**
2. **was this output expected to reproduce exactly?**

Required provenance fields:

```text
judge_id
judge_version
execution_mode
model
model_revision
weights_digest
inference_engine
inference_engine_version
quantization
decoding_determinism_class
seed
generation_parameters
judge_prompt_version
rubric_version
```

Fields that do not apply must be explicitly null rather than silently omitted where the schema requires them.

### Decoding determinism class

`decoding_determinism_class` is a first-class categorical field, not an inferred property of `generation_parameters`.

Initial values:

```text
deterministic
seeded_stochastic
unseeded_stochastic
unknown
```

The local adapter requires this field to be supplied explicitly. It does not infer determinism merely from `temperature=0` or the presence of a seed.

## Local/open-model adapter boundary

`scripts/local_openai_compatible_judge.py` supports only loopback `http`/`https` endpoints such as a local OpenAI-compatible inference server.

It intentionally:

- rejects non-loopback hosts;
- requires explicit model identity and rubric version;
- carries optional model revision, weights digest, inference-engine version, quantization, and seed;
- emits a normal `JudgeResponse` through the same subprocess boundary as the mock judge;
- adds no inference or provider SDK to the base runtime.

Hosted endpoints belong to a later explicit integration decision.

## Human calibration boundary

A real semantic judge must be evaluated against blinded human/domain-expert labels. Judge self-consistency or agreement with another LLM is not sufficient evidence of semantic correctness.

The current calibration harness uses opaque item IDs so judge records and human labels can be joined without embedding adjudication context in the runtime path. It reports simple agreement and confusion counts only.

Before any ADR-0015 decision, calibration should include at minimum:

- clear PASS examples;
- clear FAIL examples;
- deliberately ambiguous/REVIEW examples;
- documented judge/human disagreements;
- the exact judge provenance for every record.

No threshold for semantic-only FAIL authority is defined yet.

## Claims boundary

Until real-model calibration evidence exists, V1.6 semantic-judge outputs are **prototype evaluation-engineering evidence** only.

Do not describe semantic-judge outputs as clinical ground truth, validated expert judgment, comprehensive safety evidence, statistically validated performance, or release authorization.
